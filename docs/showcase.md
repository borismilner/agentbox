# The showcase: the deck, and what happens on screen beside it

> **Frozen on 2026-08-06.** Boris dropped the showcase for good: no re-record, no
> re-upload, nothing here is maintained. The numbers below (the tool count above
> all) were already stale when it was frozen, and correcting them is not work
> anybody owes. Kept for the record, not as instructions.

This is the presenter's copy of a demo that runs itself. The deck is
`docs/agentbox-showcase.pptx`, generated by `tools/showcase/deck.py`; the narration
lives in that deck's speaker notes; `tools/showcase/perform.py` speaks the notes
and drives the machine in step with them, and `tools/showcase/take.sh` does the
whole thing with the camera rolling. Twenty-two slides. Measured on the 2026-07-25 take: 17 min 27 s with the
narration, and about seven minutes for a silent rehearsal.

Every card in it is real. Nothing is a mock-up, nothing is a screen recording of
something that happened last week, and every answer travels back through the socket
to code that was blocked on it.

**It is written for somebody who has not bought in yet.** The story is one team's
afternoon - a release going out, a job being watched, a token being handed over, a
diff being approved - because the natural example of each tool is the one a viewer
recognises from their own week. Four agents send questions over the course of it
(`release-bot`, `test-runner`, `dependency-bot`, `oncall-helper`, all on project
`checkout-api`), so the inbox and the insights tab show a real distribution rather
than one demo name.

**The pointer is never the subject.** AgentBox drives its own demo, which is how the
cards get answered with nobody in the frame - and the audience is never told. It had
a reveal of its own once, two slides of it, and both came out: a room that starts
watching the mouse has stopped watching the product. Keep it out of the narration,
out of the slides, and out of the commands you put on screen.

**Nothing addressed to a presenter belongs on a slide.** No file names, no act
numbers, no notes about what to sell hardest. That is what this file is for.

## The argument, in one page

Use this if you have two minutes instead of eighteen.

**The problem.** An agent works for twenty minutes while you are somewhere else.
When it needs one word from you, it has nowhere to put the question. So it does one
of two things, and both cost you: it stops and waits in a terminal nobody is looking
at, or it decides for itself and you find out later, in the diff. Either way you end
up sitting next to it, which is the opposite of why you started it.

**The idea.** Give every agent on the machine one place to reach you, and make being
reached cheap: a card over whatever you are doing, a sound that says what kind of
thing arrived before you look, and an answer that goes straight back to the code
that is blocked on it.

**What it buys.** An agent you can leave running for an hour, because the moment it
needs a person it has somewhere to put the question. You answer the few things that
need judgement instead of approving every command. And nothing that arrives while
you are away is lost.

**What it is.** One Go binary and a resident daemon. Fourteen tools over MCP, the
same fourteen over a CLI for shell scripts, hooks and cron. No cloud, no account, no
telemetry, nothing leaving the machine. Register it once and every agent in every
project can reach you.

**Why it can be trusted with real work.** Three questions, three straight answers.
*Can it leak a secret* - no: a credential goes from the keyboard to a 0600 file and
the agent gets a path; the log records that a secret was asked for, never what it
was. *Can agent-authored content phone home* - no: an artifact runs with no network
at all and an image may name a local file and nothing else, both enforced by tests.
*Can I switch it off* - yes: do-not-disturb, per-agent mute, quiet hours, and the one
level that pierces DND can be turned off too.

**Where it is going.** Away delivery, so a question that matters can reach you
when you are not at the desk at all; whole agent sessions run from the panel; the same window handling on
Wayland, with packages. Say this out loud - a stakeholder wants to know the thing is
alive, not finished.

## Preflight (do all of this before the first slide)

```bash
agentbox status                     # a daemon must answer; note the build
agentbox drive where                # "0 0 1920 1200" - proves XTEST is there
agentbox dnd status                 # remember it; restore it at the end
agentbox dnd off                    # the tour needs cards to actually appear
agentbox logs | grep speech.engine_started | tail -1   # the voice is up
```

Then clear the stage. **A warning, error or urgent notice has no dismiss deadline
by design** - it waits to be read - so anything left from earlier will sit in
front of the first slide:

```bash
while agentbox drive where "=agentbox" >/dev/null 2>&1; do
  agentbox summon; sleep 0.4; agentbox drive key shift+Escape; sleep 0.5
done
```

`shift+Escape` dismisses. Plain `Escape` **defers** (requeues for five minutes),
which means the card comes back in the middle of a later slide.

### Rehearse first. Always.

```bash
tools/showcase/take.sh                 # rehearsal, then the take, both gated on one click
tools/showcase/take.sh --no-rehearse   # only if you have just rehearsed
.venv-deck/bin/python tools/showcase/perform.py --rehearse --park 1130,540
```

The rehearsal is the take without the camera and without the voice: every window
opened, every click driven, every card answered and checked, the deck's fullscreen
state verified at the end of every slide, and a timing table at the end that says how
long the real take will be. It costs about seven minutes and it is not optional.

The take of 2026-07-25 22:33 ran seventeen minutes and had to be thrown away: nine
wheel notches meant for a document window landed on the slideshow instead, each notch
advanced a slide, the show ran off its end and closed itself, and **nothing noticed for
the remaining four minutes**. Three separate defects were in that one recording (below),
and a rehearsal would have caught all three before the camera rolled.

### Nine things that will otherwise cost you a take

| Trap | What to do |
| --- | --- |
| A window titled `agentbox` is not always the card - a terminal whose title contains "agentbox" matches too. | Always target `"=agentbox"` (the `=` means exact) or `"=agentbox · Title"`. |
| Card heights come from an *estimate* of the content, so a two-line body puts the buttons ~23px lower than a one-line body. | The offsets below are measured against **the card text in `perform.py`**. Re-measure if you change a body. |
| An answered card lingers for the FR28 undo grace before the answer ships. | Wait for the blocking command to return rather than sleeping a guess. |
| Notifications queue: one window at a time. | Fire, hold, dismiss, then fire the next. That is what makes five earcons audible as five. |
| Two daemons cannot both map windows on one X display. | Perform against the **deployed** daemon. Its inbox picks up the tour's items, which slide 17 then shows off. |
| In zsh, an **unquoted** `=agentbox` is equals-expanded to the path of the `agentbox` binary, so the window lookup silently searches for a window titled `/home/you/.local/bin/agentbox`. It cost a take. | Always quote it: `"=agentbox"`, and `local t="${1:-=agentbox}"` inside a helper. |
| **A wheel notch goes wherever the pointer is standing.** `window TITLE` sets the frame that coordinates are read in; it does not move the pointer. A `scroll` after a `park` therefore scrolls the slideshow, and in an OnlyOffice slideshow one notch is one slide - nine notches ran the deck off its end and closed the show. **This ruined a whole take.** | Every scroll gets a `move` into its window first. `perform.py`'s `lint_plan()` refuses a scroll that has no move in front of it, and refuses coordinates with no `window`/`screen` frame. |
| **A backgrounded command with `capture_output` blocks anyway.** `subprocess.run("agentbox veto ... &", capture_output=True)` waits for the pipe to close, which means it waits for the veto's whole countdown: the card came and went inside one step and the narration then described a card that was gone. | Use `("bg", ...)`, which is `Popen` with `DEVNULL`. `sh()` now also treats a trailing `&` as background. |
| **AgentBox used to type on the group that was active, not the one it planned for.** With a second layout selected (`us,il,us` here), the release tag `2026.7.3` reached the card as `2026ץ7ץ3` - on camera. | Fixed in `internal/hand/xkb.go` (2026-07-28): every synthetic key press locks the planned group first, verified live with Hebrew active. The old workaround - writing `input-sources current` via gsettings - was removed after measuring that GNOME 46 ignores that key entirely; it never protected anything. |
| **Nothing used to notice a ruined stage.** The slideshow closed at 13:04 of a 17:27 take and the performance carried on for five more slides. | `perform.py` checks the deck is still fullscreen at the start of every slide and after every input step, and stops the run the moment it is not. `take.sh` then cuts what it has and says so. |

### Every window goes to the monitor the pointer is on

Cards, toasts, the viewer, the artifact, the app window and the panel are all placed
on the *active* monitor, which is the one the pointer is on at the moment the window
opens (`internal/webui/x11.go` `place`, `corner`, `panel.resolve`). A take records
one monitor, so `perform.py` parks the pointer there before the first slide and after
every run of input. If a window opens on the wrong screen, the pointer was on the
wrong screen.

### Re-measuring a card (30 seconds)

```bash
read x y w h < <(agentbox drive where "=agentbox")
import -window root -crop ${w}x${h}+${x}+${y} +repage /tmp/card.png
```

Then look at `/tmp/card.png` and convert: a control whose centre sits at `cy` in a
window `h` tall is `-(h - cy)` from the bottom. Write coordinates as edge-relative
(`-94`) or fractional (`50%`) so they survive a resize.

### Coordinates, all measured 2026-07-25 against the deployed daemon

Every row below was driven, answered and checked with the card text `perform.py`
actually sends - not derived from an earlier table.

| Card | Size | Control | Step |
| --- | --- | --- | --- |
| ask, 1-line body, 3 options | 470x214 | first option | `click 60 -74` |
| input, 1-line body | 470x280 | the field | `click 50% -123`, then `key Return` |
| confirm, 1-line body | 470x214 | either answer | `agentbox summon`, then `key y` (or `n`) |
| secret, 1-line body | 470x280 | the field | `click 50% -150`, then `key Return` |
| form, 3 fields | 470x310 | select / its 3rd option / text field / checkbox / Submit | `click 64% -212` / `click 64% -123` / `click 64% -162` / `click 33 -126` / `click -52 -92` |
| review, 1-line body, 11-line diff | 470x465 | note / Request changes / Approve | `click 50% -101` / `click -165 -59` / `click -55 -59` |
| viewer and artifact | 900x780 | close | `click -19 18` |
| app window | 1080x860 | rail: session, inbox, history, document / settings / close | `click 27 65`, `27 103`, `27 141`, `27 179` / `click 27 -29` / `click -21 18` |
| artifact (`console.jsx`) | 900x780 | slider drag to exactly half / Start the rollout / Hold it | `drag 14% 47% 50% 47%` / `click 26% 86%` / `click 73% 86%` |
| report (`tour.md`) | 900x780 | top to bottom | `scroll 9` three times |

**A one-line body is 214px and a two-line body is 234**, and the option chips sit a
fixed distance above the footer, so the offset moves with the body. `click 60 -94` is
the two-line number; the ask card in this tour has a one-line body and takes `-74`. If
you rewrite a body, re-measure or keep it to one line.

**An answered card stays on screen for the FR28 undo grace** - `grace_ms`, 3000 by
default - and only then does the blocking command return. A check that looks for the
card 0.7s after the click calls a good click a miss: `perform.py`'s `submit` polls for
4.5s before it decides to fall back to Return.

**In zsh, an unquoted `$FLAGS` does not word-split.** `$K ask $ID --title …` passes
`--agent release-bot --project checkout-api` as one argument and the command dies with
"flag provided but not defined". Write the flags out, or use `${=ID}`.

The artifact's three bands are equal thirds on purpose: percentages of the window are
what let a script aim at it, so keep them if you rewrite the interface.

### Narration

You do not read it. `perform.py` does, from the deck's speaker notes, one beat per
blank-line-separated paragraph, each spoken with **`agentbox say --wait`** - which
returns when the audio has actually stopped rather than after a guess. That is what
keeps twelve minutes of voice in step with the slides without one hand-tuned sleep.

Two rules the plan enforces, and a rewrite must keep:

- **A slide's beats are all spoken before it advances**, so no slide is cut off
  mid-sentence. `perform.py` warns at startup if a slide narrates a different number
  of beats than the plan places.
- **Beats sit between the actions, not after them.** A card goes up, a beat plays
  over it, the card is answered, the next beat comments on what happened. A long
  silent hold at the end of a slide is the failure mode; write another beat instead.

Cards carry their own `--speak` line, which arrives with the earcon and is *not*
waited on - that is what keeps the five-level slide from being twenty seconds of
silence between chimes.

## What each slide shows

Slides with no entry are words only: the voice carries them and nothing happens on
screen. `perform.py --from N --to M` rehearses a range.

### 2 - the problem

One info card, under the slide that names the problem: *This is AgentBox. An agent is
about to interrupt you about fifteen times, on purpose.* An audience that knows the
count watches for the cost.

### 6 - five levels, five sounds

Five notifications from three different agents, one at a time, held ~3.5s each
(4.5s for urgent) and dismissed before the next: a finished dependency scan, green
tests, a disk at 86%, a failed nightly build, a climbing production error rate.

**The point of the act:** the first two take themselves off the screen, the last
three wait to be read, and urgent is the only one that pierces do-not-disturb.

### 8 - a decision, in two seconds

Three shapes in a row, each answered a different way:

```bash
agentbox ask     --title 'Where should this release go?' --option Staging --option Production --option 'Hold it'
agentbox input   --title 'What should I tag it?'          # typed: 2026.7.3
agentbox confirm --title 'Run the migration on staging?'  # answered with the y key
```

**Checks:** `{"answered":true,"answer":"Staging"}`, then `"reply":"2026.7.3"`, then
`"answer":"yes"` and exit 0. Say that `n` is exit 1, so a shell script can branch on
a human's answer with no parsing at all.

### 10 - act unless stopped, then one card for three questions

`agentbox veto --in 12` on the staging certificate rotation, narrated over the countdown
and allowed to elapse - **do not pass `--json` here**: on the wire an elapsed veto is
nobody answering, so the object reads `{"answered":false}`, which is correct and
looks like a failure on a screen. The bare word `proceeding` is the demo.

Then a three-field form (target, ticket, migrate). The dropdown is opened and
`canary` is picked, which is the proof: it is not the default, so the select was
really used. WebKitGTK draws that popup inside the page rather than as a separate X
window, which is why a plain click reaches it; the option rows sit ~23px apart.

**Check:** `"values":{"migrate":"true","target":"canary","ticket":"REL-482"}`.

### 11 - the progress bar

A reindex reports 17 times over about half a minute into its own window, in a corner,
which never takes focus and never covers the middle of the screen where a question
would land. One success chime at the end.

### 13 - a secret, and the off switch

The passphrase types itself as dots; the agent gets a path, not a value.

```bash
stat -c '%A  %n' /tmp/agentbox-showcase-token    # -rw------- ...
```

Then `agentbox dnd on`, a routine notice that **does not appear** (that silence is the
check - it is in the inbox), and an urgent one that comes through anyway. `agentbox dnd
off` at the end, or back to whatever preflight recorded.

### 14 - the review card

A real unified diff, coloured, in the card: an `http.Client` with no timeout getting
one. Both narration beats are spoken with the diff on screen, which is also how long
a person needs to read it, and then it is approved.

**Check:** `{"answer":"approved","approved":true}`. The other button returns
`rejected`, and a typed note comes back as `reply`, so "changes requested, and here
is why" is one round trip.

### 16 - the artifact

`tools/showcase/console.jsx`: the canary decision, as an interface. A slider for the
share of live traffic, a bar underneath saying what that share means in requests a
minute, and two buttons. An agent is parked on it, blocked:

```bash
id=$(agentbox show --artifact --title 'Canary rollout' tools/showcase/console.jsx | tail -1)
agentbox artifact wait --id "$id" --name rollout --timeout 180     # this BLOCKS
```

**Check:** the blocked call prints `rollout {"action":"start","percent":50}` (verified
2026-07-25 against the deployed daemon). The drag arrives as one value rather than
forty, because repeated events of one name coalesce - `agentbox artifact read --id "$id"
--name percent` shows the latest.

It is a WebKit window and takes a moment to paint, so the first hold is 4s: the
narration must not talk over a blank frame.

### 17 - the report, and the record

`tools/showcase/tour.md` in the reading window - a table of what shipped, real
mathematics for the rollout decision, a mermaid pipeline, a chart of the week,
highlighted code and an image read off this disk - scrolled while the voice walks
through it. Then `agentbox app --tab inbox`, and two more of the rail: history, which is
the tab that answers "what did this cost me", and settings.

**The history tab shows real agent names, so it shows whatever has actually been
asking on this machine** - `showcase`, `zsh`, `probe` and `placement` from rehearsals
alongside `claude` and `systemd`. **Boris decided (2026-07-25) to leave it that way:**
the honest table is the point of the slide, and a tidied one would be a nicer lie. Do
not prune it before a take, and do not offer to.

If a future audience ever needs the rehearsal rows gone, it is a delete against his own
history and therefore his call, not a step:

```bash
systemctl --user stop agentbox.service
sqlite3 ~/.local/state/agentbox/agentbox.db \
  "delete from items where agent like '%-demo' or agent in ('showcase','nudge','probe','placement','dbg','grabbit');"
systemctl --user start agentbox.service
```

**The claim to make here:** nothing on that page reached the network, and that is
enforced by a test that runs a hostile document through every surface rather than by
a promise in a readme.

### 19 - the panel

`ctrl+alt+`` rolls the console down over whatever was there, with a live session
already in it. A sentence is typed and sent; a real `claude` child answers, streaming.
**It spends tokens** - say so if the room is paying for it.

Read the reply out loud, because the reply is the act: it knows what AgentBox is and how
it is expected to interrupt, not because the prompt said so but because every session
AgentBox starts is handed that briefing (`agentbox docs session`).

What can go wrong here, and it has:

- **`where` cannot find it.** `hand` refuses a window under 16px, so a panel that is
  still one pixel tall reads as absent. If it stays that way the roll failed - do not
  type, because the keystrokes will go to whatever is behind it.
- **The reply takes twenty seconds.** That is a model thinking, not a hang. The turn
  shows a 24-hour clock and how long it worked; let the room see it arrive.
- **The cost.** Off by default (`[session] show_cost`); turn it on before the demo if
  the room is the kind that asks.

### 22 - the close

One success card that finishes the story the tour told - *Release 2026.7.3 is live.
Canary at 50% for thirty minutes, error rate flat. Nothing needs you.* - then the
sale: your agents run unattended, and you get pulled in for the decisions that are
actually yours.

Restore what preflight recorded (do-not-disturb) and dismiss the last card.

## If something misses

- **No card appeared.** Something sticky is in front of it, or the queue is busy:
  run the clear loop from preflight, then `agentbox status` for the pending count.
- **A click did nothing.** The offsets are measured against the card text in
  `perform.py`. Re-measure with the recipe above; do not keep clicking. `submit`
  presses Return if the click missed, so a take survives it - but the video shows a
  card being answered by a keystroke where you promised a click.
- **A window opened on the wrong monitor.** The pointer was on the wrong monitor when
  it opened. `perform.py --park X,Y` (`record.sh park` prints the pair) and it parks
  there before the first slide.
- **Keys went to the wrong place.** AgentBox's windows deliberately do not take focus.
  `agentbox summon` first, or click inside the window - a click in an artifact's iframe
  works without focus, a keystroke does not.
- **The voice talks over itself.** A narrated line went out without `--wait`. That is
  the fix; do not lengthen a sleep or shorten the sentence. If `--wait` itself came
  back early, the daemon is an old build - `make deployed` reports which one is
  serving.
- **You have four minutes, not eighteen.** Perform 1, 2, 3, 8, 9, 10, 14, 16, 19, 22:
  the problem, the idea, the two-second answer, the countdown nobody stops, the
  review, the interface the agent wrote, the panel, and the close.
