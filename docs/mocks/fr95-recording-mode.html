FR95 - get the strip out of a screen recording

You asked for the hands-off panel to be hidable while recording, and settled the shape the same day: demoted, not hidden, down to FR74's four-pixel marker, and the demoted marker gives up being top-most so a window can cover it. Drive the stage. The frame on the right is what the recording exports. Four questions at the bottom; the fourth is one this mock turned up. Nothing here is built.

The stage

This stage is 1920x1200 at 40%, so everything is to scale: the strip is 620x62, GNOME's top bar is 32, and the marker's four pixels are drawn as two. That is the argument, at the size the argument actually happens.

Measured on your desktop today, not assumed

  • VISIBLE A frameless 4px window at +0+0 is visible over GNOME's top bar with no notification type and no _NET_WM_STATE_ABOVE at all. This was the risk that could have killed the whole shape: if the shell's own bar drew over it, a demoted marker would be no sign at all, which is the one wrong answer FR74 names.
  • NEVER Today's marker keeps the notification type, and it is already proved that a notification window cannot be pushed under a fullscreen one (x.lower() is called and Mutter ignores it). Re-measured today and unchanged. So the only way to make the sign coverable is to give up that window type, which is exactly the relaxation you asked for.
  • OPEN Whether AgentBox's own marker window, with the type dropped, is then covered by a fullscreen window. A bare probe window would not go under one however it was hinted, so the probe is not a faithful stand-in for the real Wails window: this gets answered by building it and watching it, at the top of the build, before anything is designed around it.
  • TRAP Two ways this measurement lies, both hit today. import -window root cannot see a fullscreen window at all (Mutter unredirects it, so the root pixmap still holds what is underneath) - use gnome-screenshot. And while an agent holds the desktop, a fullscreen window makes AgentBox open its own marker at +0+0, so anything measured at the top edge mid-run is measuring AgentBox.

The four questions

Where this lands if it is built. Small, and that is the point of reusing FR74's answer. internal/webui/control.go already has openMark, the keeper and the step-aside rule in planMark; demoted mode is a second reason to open the marker and a flag that says "map it and leave it alone" (no prepare(xid, true), no above, no raise on the beat). internal/daemon/control.go holds the mode beside FR94's latch so both can be true at once. frontend/src/surfaces/Mark.svelte gains the paused colour. What FR74 already does for free: whenever the focused window is fullscreen the strip steps aside to the marker today, with no recording mode at all. What FR95 adds is the marker without fullscreen, and a marker that a fullscreen window can cover.
